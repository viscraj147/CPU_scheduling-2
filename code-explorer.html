1. Process Control Block Struct: Process.hpp Memory Offset: 32 bytes
Data Structure: Contiguous C++ Struct
Time Complexity: O(1) attribute access
Space Complexity: O(N * sizeof(Process))
// Contiguous struct memory representing each Process in the scheduling table
struct Process {
    int id;              // Process ID (PID)
    int arrival;         // Arrival Time in milliseconds / ticks
    int burst;           // CPU Burst duration required
    int remaining;       // Remaining CPU execution time
    int priority;        // Process priority (lower numeric value = higher priority)
    int completion;      // Time at which process finishes execution
    int waiting;         // Total time spent in ready queue (TAT - Burst)
    int turnaround;      // Total lifespan from arrival to completion (CT - AT)
    int response_time;   // First time CPU was acquired minus Arrival Time
};

// Global array allocated on stack or heap:
Process p[50]; // Bounded contiguous array for processes
Why it matters: Demonstrates that process tables in operating system kernels (like Linux task_struct) are contiguous memory records indexed by PID or task pointer.
2. Linear Array Traversal for Process Selection Function: select_next_sjf()
Data Structure: Linear Array Search
Time Complexity: O(N) per selection
Operation: Minimum burst comparison scan
// Linear scan to find the arrived process with the minimum burst time
int select_next_sjf(Process p[], int n, int current_time) {
    int min_burst = 1e9;
    int selected_idx = -1;

    for (int i = 0; i < n; i++) {
        // Condition: Process has arrived and still has remaining CPU time
        if (p[i].arrival <= current_time && p[i].remaining > 0) {
            if (p[i].remaining < min_burst) {
                min_burst = p[i].remaining;
                selected_idx = i;
            } else if (p[i].remaining == min_burst) {
                // Tie-breaking policy: Earliest arrival time, then smallest PID
                if (selected_idx != -1 && p[i].arrival < p[selected_idx].arrival) {
                    selected_idx = i;
                }
            }
        }
    }
    return selected_idx; // Returns -1 if CPU is IDLE
}
Viva Tip: While O(N) is fast for small process tables (< 100), high-performance schedulers replace linear arrays with O(log N) heaps or red-black trees.
3. Circular Queue (Ring Buffer) for Round Robin Class: CircularQueue
Data Structure: Modulo Ring Buffer
Time Complexity: O(1) Enqueue, O(1) Dequeue
Key Equation: (rear + 1) % CAPACITY
class CircularQueue {
private:
    static const int CAPACITY = 100;
    int data[CAPACITY];
    int front;
    int rear;
    int count;

public:
    CircularQueue() : front(0), rear(0), count(0) {}

    bool is_full() const { return count == CAPACITY; }
    bool is_empty() const { return count == 0; }

    // Enqueue process ID to rear
    void enqueue(int pid) {
        if (is_full()) return;
        data[rear] = pid;
        rear = (rear + 1) % CAPACITY; // Wraparound behavior
        count++;
    }

    // Dequeue process ID from front
    int dequeue() {
        if (is_empty()) return -1;
        int pid = data[front];
        front = (front + 1) % CAPACITY; // Wraparound behavior
        count--;
        return pid;
    }
};
Why Modulo: Eliminates memory fragmentation and prevents shifting elements when front items depart.

Exam & Viva Q&A
Q1: Why is a Circular Queue preferred over a standard linear array for Round Robin?
In a standard linear queue, every dequeue operation leaves unused slots at the front. To reuse them, you must shift all remaining elements, taking O(N) time. A Circular Queue uses modulo arithmetic to wrap pointers in O(1) time, completely avoiding costly array shifts.
Q2: How does Shortest Remaining Time First (SRTF) utilize a Min-Heap?
SRTF requires frequent selection of the process with the minimum remaining burst time. In an array, this requires an O(N) scan every second. By organizing the ready set as a Min-Heap keyed on remaining_time, the next process can be accessed in O(1) and updated in O(log N).
Q3: What is the convoy effect, and which data structure problem causes it?
The convoy effect occurs in FCFS when a long CPU-bound process blocks multiple short I/O-bound processes behind it in a single FIFO queue, causing high average waiting time. Multi-level feedback queues (MLFQ) solve this by maintaining separate priority queues.
Q4: What data structure preserves state during CPU context switches?
The Call Stack / Kernel Interrupt Stack. When a timer interrupt occurs, the hardware pushes program counters, CPU flags, and register states onto the stack in LIFO order, and pops them when restoring execution.
